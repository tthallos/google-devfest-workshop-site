DevFest 的第二场演讲让我见识了一个有趣的东西：**Prompt API** 和 **Nano 模型**。

简单来说，这是一个让 AI 直接在你的浏览器里运行的技术。不需要发送请求到云端，不需要等待网络响应，更不需要为每次调用付费。

听起来像是天方夜谭？让我慢慢道来。

## 为什么叫 "Banana"？

演讲的标题里有个词叫 "Nano Banana"，我一开始以为是什么新的香蕉品种（程序员的幽默，你懂的）。后来才知道，这是 Chrome 团队对这个项目的内部昵称。

"Banana" 可能来自 "Built-in AI, Not A Network Application"（内置 AI，不是网络应用）的缩写——好吧，这是我瞎编的，但听起来很合理对吧？

不管名字怎么来的，重要的是它代表的理念：**AI 应该离用户更近，而不是藏在远方的服务器里。**

## Prompt API：浏览器的新超能力

Chrome 正在开发一套新的 Web API，让网页可以直接调用内置的 AI 能力。这套 API 目前还在实验阶段，但已经可以在 Chrome Canary 里尝试了。

核心 API 非常简单：

```javascript
// 检查是否支持
const available = await ai.languageModel.availability();

if (available !== 'unavailable') {
  // 创建会话
  const session = await ai.languageModel.create();
  
  // 发送提示
  const response = await session.prompt('用一句话解释什么是 JavaScript');
  
  console.log(response);
  // 输出: "JavaScript 是一种让网页变得有生命的编程语言。"
}
```

就这么简单。不需要 API key，不需要网络请求，不需要担心费用。

## Nano 模型：小而美的 AI

支撑这套 API 的是 Google 的 Nano 模型。这是一个专门为设备端运行优化的轻量级模型，有几个特点：

### 1. 体积小巧

Nano 模型大约只有几百 MB，可以作为 Chrome 的一部分下载到本地。相比动辄几十 GB 的大模型，这简直是"减肥成功"的典范。

### 2. 速度飞快

因为不需要网络往返，响应几乎是即时的。我在演示中看到，从发送请求到收到回复，大约只需要 100 毫秒。这意味着你可以实现真正的"实时 AI"功能。

### 3. 隐私优先

你的数据永远不会离开你的设备。对于那些敏感的应用场景——比如分析私密文档、处理个人信息——这是一个巨大的优势。

## 实际应用场景

演讲中展示了几个有趣的应用场景：

### 智能表单填充

想象一下，当你在网上填写一个复杂的表单时，AI 可以根据你之前的输入，智能推荐后续字段的内容。而且这一切都在本地完成，你的个人信息不会被发送到任何服务器。

### 实时写作助手

你在写邮件或者文档时，AI 可以实时给出语法建议、措辞优化，甚至帮你总结要点。因为是本地处理，所以即使你在飞机上、地铁里，没有网络也能用。

### 内容理解与总结

遇到一篇很长的文章？AI 可以帮你快速总结要点。而且因为是本地处理，你不用担心把机密文档的内容泄露给第三方。

### 离线翻译

虽然已经有很多离线翻译 App，但如果这个能力内置在浏览器里，网页开发者就可以轻松为自己的应用添加多语言支持。

## 一些技术细节

作为一个前端工程师，我特别关注了几个技术细节：

### 模型下载

Nano 模型会在用户首次需要时下载。Chrome 会智能地决定下载时机，避免影响用户体验。下载后的模型会缓存在本地，后续使用不需要重新下载。

### 上下文管理

每个 AI 会话都有一个上下文窗口，用于存储对话历史。开发者可以通过 `session.countPromptTokens()` 来检查当前使用了多少 token，避免超出限制。

```javascript
const tokens = await session.countPromptTokens('这是一段测试文本');
console.log(`这段文本使用了 ${tokens} 个 token`);
```

### 流式响应

对于较长的回复，API 支持流式输出：

```javascript
const stream = await session.promptStreaming('写一首关于编程的诗');

for await (const chunk of stream) {
  console.log(chunk); // 逐字输出
}
```

这让用户可以看到 AI "正在思考"的过程，体验更加自然。

## 我的一些担忧

当然，作为一个习惯了怀疑一切的程序员，我也有一些担忧：

### 模型能力有限

Nano 毕竟是一个轻量级模型，它的能力无法与 GPT-4 或 Gemini Pro 相比。对于复杂的推理任务，它可能力不从心。

演讲者也坦诚地说："Nano 不是用来取代云端大模型的，它是用来处理那些简单但频繁的任务。"

### 碎片化风险

目前只有 Chrome 支持这套 API。如果其他浏览器不跟进，开发者就面临一个尴尬的选择：要么只支持 Chrome 用户，要么还是得用传统的云端 API。

好消息是，这套 API 正在 W3C 标准化过程中，未来可能会被更多浏览器采用。

### 资源消耗

虽然 Nano 模型很轻量，但 AI 推理毕竟需要计算资源。在低端设备上，这可能会导致性能问题。

演讲中提到，Chrome 会根据设备性能动态调整 AI 能力。在性能不足的设备上，某些 AI 功能可能被禁用。

## 一个有趣的思考

走出演讲厅，我在想一个问题：**当 AI 变得无处不在，我们还需要程序员吗？**

我的答案是：**需要，而且更需要。**

因为 AI 降低的是"实现"的门槛，而不是"创意"的门槛。任何人都可以让 AI 写一个 Hello World，但要设计一个真正有价值的产品，还是需要人来思考：

- 这个产品解决什么问题？
- 用户真正需要什么？
- 如何将 AI 能力与业务需求结合？

正如王小波说的：

> 我认为低智、偏执、思想贫乏是最大的邪恶。

AI 可以帮我们摆脱低智和繁琐，但思想的丰富，只能靠我们自己。

## 如何体验

如果你想尝试 Prompt API，可以按照以下步骤：

1. 下载 Chrome Canary（金丝雀版）
2. 打开 `chrome://flags`
3. 搜索 "Prompt API" 并启用
4. 重启浏览器
5. 在控制台中尝试 `ai.languageModel.availability()` 检查是否可用

注意：这是实验性功能，不建议在生产环境使用。
